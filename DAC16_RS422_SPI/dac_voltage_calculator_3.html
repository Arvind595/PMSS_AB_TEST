0x18 — POWERDOWN_CONFIG

Single byte. Bit 4 = CH0_DAC_POWERDOWN (0 = normal operating mode, 1 = powered down). The DAC core powers down on reset and must be brought up before use — writing 0x00 here powers it up. This matches the "Reg 0x18 <= 0x00 (Power up DAC)" step in dac_ad3551r_ch.vhd exactly.

0x19 — CH0_OUTPUT_RANGE

Single byte, bits [3:0] = CH0_OUTPUT_RANGE_SEL. Selects one of five predefined spans; the matching RFBx_0 feedback resistor must physically be populated for the selected span to be valid.

This project uses code 0x04. The "Actual" columns aren't exactly symmetric round numbers — Analog Devices bakes in ~3% overrange per predefined span on purpose, so 0x0000/0xFFFF land a bit past the nominal ±10 V rather than exactly on it. Both this tool's ±10 V preset and the uv_to_code function in dac16_uart_controller.vhd now use these exact VZS/VFS values — a request is still clamped to the nominal ±10 V instrument range, but converts against the true span so, e.g., a request for exactly +10.000V lands on the correct code instead of 0xFFFF.

0x29 / 0x2A — CH0_DAC_16B (Fast Mode DAC register)

16-bit register split across two addresses: 0x2A = data bits [15:8] (high byte), 0x29 = data bits [7:0] (low byte). Writing this register updates the output immediately (no LDAC dependency for this path). The part's reset defaults — INTERFACE_CONFIG_A = 0x10 (ADDR_DIRECTION = 0, descending) and INTERFACE_CONFIG_B = 0x08 (streaming mode enabled) — mean a single SPI write of address 0x2A followed by 2 data bytes MSB-first lands the high byte at 0x2A and auto-decrements to write the low byte at 0x29, exactly matching the 24-bit SPI frame (0x2A + 16-bit code) this project sends. No register configuration changes needed for this to work as-is.
